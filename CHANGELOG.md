# Changelog

## [0.2.0] - unreleased (port/off-windows-shared)

simple_browser off Windows, the shared code and the Windows engine (SIMPLE_BROWSER_SPEC.md, port-coordination #72).

### Security
- 2026-11-26: `lib/WebView2Loader.dll` 1.0.1150.38 to **1.0.4370.26** and `Clib/windows/WebView2.h`
  to the same SDK (Microsoft's NuGet package `Microsoft.Web.WebView2` 1.0.4370.26, 2026-11-21;
  package SHA-512 as NuGet's catalog publishes it; the DLL is signed by Microsoft Corporation).
  webview.dll loads the loader by name (`GetProcAddress`), so the new export order does not
  matter. Removed `lib/WebView2LoaderStatic.lib`: nothing links it (webview.dll has its own
  loader for when the DLL is absent). simple_scholar's `bin/` carries the same loader.

### Added
- `SIMPLE_BROWSER`: `evaluate` (results of a script as JSON, promises awaited), `on_navigation`
  (`SB_NAVIGATION`: url, kind, main frame; True allows), `on_new_window`, `on_title`, `on_loaded`,
  `make_ephemeral`, `make_ephemeral_with_window`, `make_with_window`, `remove_call`, `is_closed`, `is_stopping`.
- `SB_SCRIPTS`: the bridge script (`window.__sb`), each binding's line, the answer script and the evaluate
  wrapper's body, the same text on every platform.
- `SB_BUNDLED_SCRIPTS`: htmx 2.0.4 and Alpine.js 3.14.8, from `assets/` (with their licenses), generated by
  `tools/generate_bundled_scripts.py`. `load_htmx_page` writes them inline; unpkg.com is no longer used.
- `SB_PLATFORM` per platform cluster (`src/windows` here), the only place an engine class is named.
- Tests: the shared tests of the spec's section 5 (`lib_tests`), all on an ephemeral browser.

### Changed
- `BROWSER_ENGINE` is the contract agreed for all three engines: events through a queue (`pump`, a `blocking`
  external, and `next_event`), `set_bridge`, `bind_name`, `unbind_name`, `answer` (valid JSON required),
  `evaluate`, `set_deciding`, `decide`, `show`, and test hooks. `bind`, `unbind`, `return_value` and `run`
  are gone from the engine; `is_ready` is `is_valid`.
- `run` is an Eiffel loop in `SIMPLE_BROWSER`: pump, then dispatch every queued event, until the window
  closes or `close` is called. C never calls Eiffel: `webview_wrapper.h`'s trampoline is gone.
- `respond` and `respond_error` check their text with simple_json; text that is not JSON rejects the call
  with the parse error as a JSON string.
- Size hints hold: a fixed or min hint clamps a later `set_size`; a min larger than the window grows it, a
  max smaller shrinks it. Sizes are content sizes in logical pixels.
- `WEBVIEW_ENGINE` moved to `src/windows` (a Windows-only cluster), over `Clib/windows/sb_win.h`.
  `make (a_ephemeral, a_debug)` and `make_with_window (a_parent, a_ephemeral, a_debug)`.
- Facade commands that reach the engine now require `is_valid` (the engine already did).
- Every `set_html` page loads at `https://simple-browser.invalid/page-N` (`SB_SCRIPTS.set_html_base`, numbered
  by `BROWSER_ENGINE.new_set_html_base`) on every platform: one origin rule for all three.
- Windows: navigation decisions without a deferral. Forms are held in the page and submitted again exactly
  (POST and body); fragment navigations are held through the Navigation API; the rest is canceled in
  NavigationStarting and started again if allowed. Iframe navigations are asked too (`is_main_frame` False).
  The bridge and the bindings run in the main frame only, as on the other two.
- Windows: disposing an ephemeral browser can take a few seconds (up to about 6.5 measured) while WebView2's
  processes let go of its temporary data folder, which is then deleted.
- Test hook `test_echo_at (url)`: requests for the URL are answered with their method and body.

## [Unreleased] - 2026-10-08

### Removed
- 2026-11-09: `SB_WIDGET` (the browser embedded in a simple_vision window), its `simple_browser_vision` target
  and the `demo_embedded` demo, because simple_vision is being retired. The library target is now
  `simple_browser`: the standalone browser window, unchanged. `simple_browser_web` extends it directly.

### Changed
- 2026-10-26: the `simple_browser_vision` target no longer lists ISE `wel`; nothing used it (clean build of
  demo_embedded, zero warnings).

### Fixed
- **A SCOOP or multi-threaded program froze the first time any other processor collected garbage while the
  window was open.** `webview_run` (the window's message loop, which runs for the window's whole life) was an
  ordinary external, so the runtime counted the root thread as inside Eiffel code and every collection waited
  for it forever, with all other threads spinning (simple_scholar's bible_htmx under SCOOP: 352 s of CPU, no
  request answered). It is now a `blocking` external, in the `C blocking signature ... use ...` form; the short
  `C blocking (...) | ...` form compiles but silently drops the marker. The JS-binding trampoline re-enters
  Eiffel code (`EIF_EXIT_C`) before it touches an Eiffel object and leaves it (`EIF_ENTER_C`) afterwards, and
  holds each bound object through an `eif_protect` handle instead of a raw pointer the collector could move.
- Tests: `test_binding_round_trip` (JS calls a bound routine three times, a full collection inside each call)
  and `test_gc_runs_while_the_window_loop_runs` (a worker processor runs 20 full collections while the root
  sits in the loop). Before the fix the worker took 2016 ms, stalled until the page's next callback; after it,
  0-16 ms across three runs.

### Fixed
- Removed the `demo_voxcraft_ui` ECF target: its root class never existed, so the target could only fail with VD20.
